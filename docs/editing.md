# Внести изменения в задания

Подготовьте свой форк и запустите утилиту по [README](../README.md#начать-работу). Все команды ниже выполняйте в папке своего клона.

(В целом можете не делать ничего руками, по желанию просто укажите своему ИИ-агенту что надо следовать указаниями из этого файла и потом провалидируйте его действия)

## Создать ветку

Один PR содержит изменения одного типовика. Несколько исправлений разных заданий можно объединить в один PR.

1. Если основной репозиторий ещё не добавлен, добавьте его под именем `upstream`:

	```sh
	git remote add upstream <URL_ОСНОВНОГО_РЕПОЗИТОРИЯ>
	```

2. Получите принятые изменения:

	```sh
	git fetch upstream
	```

3. Создайте ветку от `upstream/main`:

	```sh
	git switch -c ivanov/tr2 upstream/main
	```

	(в GitHub Deskstop он вроде вас при создании может спросить куда вы хотите лить, в форк или в основной репозиторий)


Используйте формат `<фамилия>/tr<N>`. Фамилию пишите строчными латинскими буквами.

## Исправить условие

1. В режиме **Редактирование** откройте нужный вариант.
2. Измените условие. Дождитесь статуса **Сохранено**.
3. Проверьте формулы и рисунки в предпросмотре. При ошибке раскройте **Журнал компиляции**.
4. Проверьте математическое обоснование исправления. Сохраните авторскую подпись.

Можно редактировать `.tex` обычным редактором. (то есть в обход веб интерфейса, но не советую так делать ибо в вебе сразу видно предпросмотр).

Для удаления используйте кнопку с корзиной: утилита сдвинет следующие номера. Кнопки отмены и повтора расположены рядом с именем файла. Сочетания: `Cmd+Z` и `Cmd+Shift+Z` на macOS, `Ctrl+Z` и `Ctrl+Y` либо `Ctrl+Shift+Z` на Windows и Linux. Отменить удаление можно до перезапуска сервера.

## Добавить новый вариант

1. Выберите номер задания.
2. Нажмите **Добавить вариант**. Утилита создаст следующий числовой файл по [шаблону](../templates/new-task/task.tex).
3. Заполните условие и авторскую подпись. Используйте [пример оформления](../templates/new-task/example.tex).
4. Если нужен рисунок, добавьте его в `TR/TRN/pic/` под свободным именем. В LaTeX укажите путь `pic/имя.png`.
5. Проверьте условие, решение и предпросмотр.
6. Приложите решение в комментарии к PR. Не добавляйте решение в файлы репозитория.

Сохраните начальную команду `\question` из шаблона. Полный документ и подключения пакетов в условие не добавляйте.

Совпадения номеров новых вариантов в разных PR разрешает ответственный при объединении.

## Отправить PR

(Аналогично все действия ниже можете сделать визуально в GitHub Deskstop если вы его используете)

1. Проверьте локальные изменения:

	```sh
	git status --short
	```

2. Добавьте файлы своего типовика и проверьте подготовленные изменения. Пример для ТР2:

	```sh
	git add -- TR/TR2
	git diff --cached
	```

	Если в подготовленных изменениях есть посторонний файл, исключите его командой `git restore --staged <путь>` до коммита.

3. Создайте коммит:

	```sh
	git commit -m "ТР2: исправил условия заданий 4 и 7"
	```

4. По желанию проверьте состав всей ветки:

	```sh
	git diff --name-only upstream/main...HEAD
	```

	В списке должны быть только пути `TR/TR2/` для этого примера. Уберите из ветки изменения утилиты, настроек, документации и других типовиков до отправки PR.

5. Отправьте ветку в свой форк:

	```sh
	git push -u origin ivanov/tr2
	```

6. На GitHub откройте PR из ветки своего форка в `main` основного репозитория. Если доступно, включите **Allow edits by maintainers**.
7. Укажите типовик и суть изменений в заголовке PR.
8. Во вкладке **Files changed** ещё раз проверьте, что PR содержит только файлы выбранного типовика.

По желанию оставьте комментарий к каждому изменённому файлу во вкладке **Files changed**: что изменили и почему. Решение новой задачи приложите независимо от этих комментариев.

Для доработки открытого PR создайте коммиты в той же ветке и повторите `git push`. После принятия PR удалите ветку в своём форке. Принятые изменения останутся в `main` основного репозитория.
