# Устройство проекта

## Каталоги и файлы

Пути указаны от корня репозитория.

| Путь | Содержимое |
|---|---|
| `TR/TR1/` … `TR/TR4/` | Актуальные условия и рисунки |
| `templates/` | Общая преамбула, начало и конец работы |
| `templates/new-task/` | Шаблон и пример нового варианта |
| `config/project.toml` | Курс, семестр, учебный период `period`, начальный `seed` распределения |
| `frontend/` | Исходник интерфейса, зависимости CodeMirror и настройки сборки JavaScript |
| `tool/web_assets/` | HTML, CSS, логотип и собранный JavaScript |
| `tool/` | Сервер, работа с файлами, распределение и сборка |
| `tests/` | Тесты утилиты |
| `Dockerfile` | Сборка образов приложения |
| `compose.yaml` | Сервисы, порт и подключённые папки |
| `docker/` | Установка TeX Live и запускатель контейнера |
| `work/students/` | Локальные CSV студентов |
| `work/assignments/<period>/<TRN>/current.json` | Текущие назначения вариантов |
| `work/build/` | Подготовленные исходники, диагностика неудачных сборок и временные данные |
| `work/exports/<TRN>/<версия>/` | Готовые PDF, ZIP, журналы, manifest и снимки назначений |
| `archive/` | Старые условия и рисунки. Утилита их не использует |
| `docs/` | Техническое описание и инструкции |
| `AGENTS.md` | Правила работы ИИ-агента в репозитории |

В `TR/TR2/4/7.tex` число `4` обозначает задание, `7` обозначает вариант. Нумерация начинается с единицы и не содержит пропусков. Каждый файл начинается с `\question`. Рисунки находятся в `pic/` соответствующего типовика.

`TR/` содержит единственный редактируемый банк. Содержимое `work/` остаётся локальным. В Git хранится только каркас этой папки. Зависимости `frontend/node_modules/` и собранный `tool/web_assets/app.js` также исключены из Git.

## Модули утилиты

Модули разделены по операциям.

| Модуль | Назначение |
|---|---|
| `tool/web.py` | HTTP API и фоновые операции сборки |
| `tool/files.py` | Чтение, сохранение, создание, удаление и восстановление вариантов |
| `tool/inputs.py` | Чтение настроек, банка и CSV, проверка входных данных |
| `tool/distribution.py` | Назначение вариантов студентам |
| `tool/render.py` | Формирование LaTeX из общих шаблонов и условий |
| `tool/preview.py` | Очередь, кэш и компилятор предпросмотра |
| `tool/compilation.py` | Компиляция полных документов и привязка ошибок к исходникам |
| `tool/service.py` | Подготовка, проверка и сохранение сборки |
| `tool/storage.py` | Запись состояния, блокировки, версии и контрольные суммы |
| `tool/migration.py` | Импорт прежних назначений ТР1 |
| `tool/__main__.py` | Терминальное меню и команды |

## Редактор и предпросмотр

Интерфейс использует HTML, CSS, JavaScript и CodeMirror. Сервер работает на Flask и Waitress.

Браузер отправляет текст серверу. Сервер атомарно записывает его в `TR/` после проверки версии содержимого. Внешнее изменение файла вызывает конфликт. Некорректный LaTeX сохраняется без требования успешной компиляции.

Предпросмотр компилирует снимок открытого условия с общими шаблонами и рисунками. Используются pdfLaTeX, TeX Live 2026 и `latexmk`, без shell escape. Предпросмотр и полная сборка используют один слот компилятора.

При запуске сервера очищаются `work/build/preview/cache/`, `work/build/preview/tmp/` и копии удалённых вариантов в `work/build/editor/deleted/`. Обновление страницы очистку не вызывает. Метрики шрифтов в `work/build/preview/fonts/` сохраняются. Предварительной компиляции банка нет.

## Распределение и сборка

Студент определяется по `ИСУ ID`. Новое распределение выравнивает частоты вариантов каждого задания внутри потока с разницей не более одного. Полные комбинации уникальны между выбранными студентами.

Обычная пересборка сохраняет назначения. Новые студенты и недоступные номера обрабатываются без общего перераспределения. Строгая равномерность прежних назначений заново не навязывается. После перенумерации прежний номер может обозначать другое условие.

Именные документы разделяются по потокам. Обзор содержит все варианты выбранного типовика без фамилий. Сборка проверяет исходники, рисунки, состав ZIP и изменения входных файлов во время операции. При ошибке компиляции частичный комплект не публикуется, новые назначения этой сборки не сохраняются.

Готовые версии и подготовленные исходники остаются на диске. Программа не проверяет математическую правильность условий и внешний вид PDF. Правки из Overleaf автоматически не возвращаются в `TR/`.

## Docker

Сервис `web` содержит приложение и LaTeX. Сервис `utility` содержит терминальную утилиту без LaTeX. Node используется только при сборке интерфейса.

Контейнеры подключают `TR/` и `work/` с правом записи, `templates/` и `config/` только для чтения. Код и интерфейс копируются в образ. Остальной репозиторий, включая `.git`, не подключается. Сведения о коммите в manifest при таком запуске отсутствуют.

Порт опубликован на `127.0.0.1:8080`. Сервер проверяет Host, Origin и сессионный токен изменяющих запросов. Файловый API отклоняет произвольные пути и символические ссылки.

TeX Live устанавливается из снимка за 5 августа 2026 года. Контрольная сумма установщика закреплена в `docker/install-texlive.sh`. Перечень установленных версий находится в образе в `/opt/texlive/manifest.txt`.

Терминальное меню запускается командой `docker compose run --build --rm utility`. Команда тестов: `docker compose run --build --rm -T utility python -m unittest discover -s /app/tests -t /app -v`. Тесты сборки используют временные данные и подменяемый компилятор.
