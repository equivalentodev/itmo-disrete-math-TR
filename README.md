# Типовые расчёты по дискретной математике

Общая утилита подготавливает проекты LaTeX для Overleaf: весь банк для проверки или именные работы по потокам. Нужен только запущенный Docker с Compose; Python и LaTeX на компьютере устанавливать не требуется.

## Запуск

Из корня клона:

```sh
docker compose run --build --rm utility
```

Первый запуск скачает Python-образ и соберёт утилиту. Последующие используют кэш. В меню:

1. **Подготовить типовик для проверки в Overleaf** — все варианты без фамилий, CSV не нужен.
2. **Собрать работы для студентов** — выбрать типовик, CSV, нужные потоки или группы. Документы всегда разделены по потокам.
3. **Создать новое распределение** — явно переназначить варианты выбранным студентам. Предыдущие версии сохраняются.

Поместите CSV в `work/students/`. Колонки: `ИСУ ID`, `ФИО`, `Поток`, `Группа`. Поддерживается UTF-8 с BOM; остальные колонки игнорируются. Ограничений по номерам групп в коде нет.

Готовые архивы находятся в `work/exports/<типовик>/<версия>/`. Утилита выводит точный путь. Загрузите **ZIP целиком** в Overleaf как новый проект. Для обзора главный файл — `dump.tex`, для именных работ — по очереди `flow_3.tex`, `flow_4.tex` и т. д. Все нужные рисунки уже внутри.

## Назначения и версии

Обычная пересборка использует сохранённые назначения: исправление текста не меняет варианты студентов. Новым студентам назначаются варианты, отсутствующие номера автоматически заменяются с сообщением.

Новое распределение обеспечивает равномерность каждого задания **внутри каждого потока**: частоты вариантов отличаются не более чем на одного. Полные комбинации уникальны между всеми выбранными студентами. При точечном обновлении старых назначений строгая равномерность заново не навязывается.

Готовые ZIP версионируются и не перезаписываются. Рядом лежат manifest и снимок назначений. Они не нужны для компиляции — в Overleaf загружается только ZIP.

Название курса, семестр, идентификатор учебного периода и начальный seed — в `config/project.toml`. При следующей выдаче задайте новый `period`, чтобы не использовать прошлогодние назначения.

## Структура

| Путь | Назначение |
|---|---|
| `TR/TR1` … `TR/TR4` | Единственный редактируемый банк условий; рисунки в `pic/` каждого типовика |
| `tool/` | Общая утилита |
| `templates/` | Оформление и шаблон новой задачи |
| `config/` | Общие реквизиты |
| `work/students/` | Локальные списки студентов |
| `work/assignments/` | Локальные сохранённые назначения |
| `work/build/` | Предварительные исходники |
| `work/exports/` | Готовые ZIP и версии |
| `archive/` | Старые задания на всякий случай, обычно не нужны |
| `docs/` | Решения, план и сведения о проекте |

`TR/TR2/4/9.tex` — девятый вариант задания №4 второго типовика. В `work/` нет второй редактируемой копии банка. Локальные списки и результаты исключены из Git.

Как предлагать исправления и новые задачи — в [CONTRIBUTING.md](CONTRIBUTING.md). Правила работы агента — в [AGENTS.md](AGENTS.md).

## Ограничения

Утилита проверяет входные данные, структуру и комплектность, но не доказывает математическую правильность заданий и не компилирует PDF. Правки, внесённые в Overleaf, нужно отдельно перенести в `TR/`.

В ТР3 и ТР4 уже существовали отсутствующие ссылки на рисунки (описаны в `docs/Очистка репозитория.md`). Сборка такого банка сообщит точный файл и рисунок; программа не подставит изображение из архива по совпадению имени.

Автоматическая проверка:

```sh
docker compose run --build --rm -T utility python -m unittest discover -s tests -v
```
