# Правила работы в репозитории

## Назначение и ограничения

Репозиторий используется для подготовки типовых расчётов по дискретной математике первого курса. Главные приоритеты — математическая точность условий и корректность вёрстки. Общайся с пользователем по-русски, объясняй существенные выводы и не соглашайся с ошибочными утверждениями ради согласия.

**Не изменяй условия задач без прямого разрешения пользователя.** Проверка, перенос и вёрстка не разрешают менять текст, обозначения, данные или добавлять ограничения. Техническое оформление допустимо с сохранением формулировки и смысла. Ответ пользователя о трактовке фиксируй в журнале; сам по себе он не является разрешением менять условие. Сохраняй авторство, кроме прямо порученных изменений.

Агент подготавливает и проверяет исходники LaTeX. Компиляцией и просмотром PDF занимается человек: не запускай компиляцию и не требуй просмотра PDF для завершения поручения. Проверку исходников не представляй как подтверждение внешнего вида PDF. Не обещай отсутствие всех ошибок.

## Актуальная структура

| Путь | Назначение |
|---|---|
| TR/TR1/ … TR/TR4/ | Единственный редактируемый банк условий и рисунков |
| tool/ | Общая утилита для всех типовиков |
| templates/ | Общие шаблоны документа и примеры новых задач |
| config/project.toml | Курс, семестр, учебный период и seed |
| work/students/ | Локальные CSV студентов |
| work/assignments/ | Локальные сохранённые назначения по периоду и типовику |
| work/build/ | Предварительные проекты, включая сохранённые материалы legacy-TR1 |
| work/exports/ | Версионированные готовые ZIP, manifest и снимки назначений |
| archive/ | Запасные старые задания, автоматически не используются |
| docs/ | Принятые решения, план разработки, инструкции и история очистки |
| CONTRIBUTING.md | Работа коллег через ветки и PR, оформление новых задач |
| Проверка первого типовика.md | Математические замечания и история ТР1 |

В TR/TR2/N/K.tex папка N — номер задания, K.tex — вариант. Числа идут последовательно с единицы. Фрагмент начинается с \question. Рисунки берутся из pic/ соответствующего банка. Количество вариантов определяй по текущим файлам, не по старым заметкам.

В work/ нет второго редактируемого банка. Её содержимое локальное, кроме инструкции и пустого каркаса в Git. Не восстанавливай work/TRN/tasks и отдельные генераторы для каждого типовика.

## Принятый процесс

Пользователь разрешил разработку общей утилиты после обсуждения требований. Полные решения — в docs/Утилита — принятые решения.md; последовательность работ — в docs/Утилита — план разработки.md. Они имеют приоритет над историческими описаниями структуры.

- Работа с условиями выполняется непосредственно в TR/ через ветки приватного репозитория и PR в main.
- Проверяющий может исправлять разные задачи в одном PR. Имена веток содержат логин автора.
- Ответственный сам убирает отклонённые изменения из ветки PR, коммитит туда и затем объединяет PR. Не навязывай cherry-pick или PR на опечатку.
- Автор сам выбирает номер задания и добавляет последовательные числовые варианты. Совпадения номеров разрешаются при объединении, без UUID и proposals/.
- Новые условия оформляются по templates/new-task/. Решение прилагается в комментарии приватного PR, а не в файлах банка.
- Исходники в Overleaf автоматически не синхронизируются с TR/. Согласованные правки нужно переносить обратно вручную.
- archive/ обычно не нужен; не смешивай его с текущими банками. Исторические пути в журналах описывают прежнюю структуру.
- Штатный запуск — Docker с русским терминальным меню; образ не более 512 МБ. При превышении согласуй с пользователем.
- Локальная компиляция PDF, веб-интерфейс и автоматические превью PR исключены. Готовые ZIP компилирует человек в Overleaf.
- Технические проверки всех четырёх банков разрешены в рамках утилиты; это не разрешение содержательно проверять или менять все условия.
- После содержательных правок веди журнал соответствующего типовика. Не меняй условия без прямого поручения.
- Следующее сообщение пользователя дополняет активную задачу, если он явно её не отменяет.

## Математическая проверка

1. Читай целиком каждый вариант, включая примечания, множества и рисунки.
2. Различай математическую ошибку, недостаток данных, неоднозначность, повтор и проблему оформления.
3. Для существенного замечания указывай файл, спорное место, обоснование и последствия для решения.
4. Перепроверяй существенные выводы независимо, когда возможно: законы множеств и полный перебор принадлежности; пары и булевы матрицы; подсчёт мощности и явные построения.
5. Несколько примеров не заменяют общего доказательства. Полный перебор допустим, когда охватывает все случаи; для опровержения достаточно проверенного контрпримера.
6. Проверяй выполнимость требований, непустоту блоков разбиения, ограничения на их число, принадлежность пар декартову произведению и определения отношений.
7. Проверяй универсум дополнений, области определения и значений, порядок композиции. Не угадывай соглашения курса; при необходимости сверяй с материалами преподавателя.
8. Пустой результат, универсум и тривиальное допустимое построение сами по себе не являются ошибками. Учитывай буквальные требования.
9. Для словесных отношений явно фиксируй необходимые модельные предположения, не подменяй их бытовыми догадками.
10. Не исправляй даже очевидную ошибку условия без прямого разрешения пользователя; при разрешении вноси только порученное.

## Генерация и передача

Запуск: docker compose run --build --rm utility. Образ содержит Python и код, без LaTeX. Команды и структура описаны в README.md.

Обзор содержит весь выбранный типовик без фамилий, с краткими номерами вариантов и правильными номерами заданий. Счётчик устанавливается внутри questions перед \question. Принудительные разрывы между вариантами и повторяющиеся шапки запрещены.

Именные документы всегда разделены по потокам. CSV сохраняет колонки ИСУ ID, ФИО, Поток, Группа; выбор потоков/групп выполняется в меню. Нет ограничения от M3111. ИСУ ID определяет студента.

Обычная пересборка сохраняет назначения. Новое распределение — отдельное действие: равномерность каждого задания внутри каждого потока с разницей частот не более одного, полные комбинации уникальны между выбранными потоками. Новые студенты и недоступные номера обрабатываются без общего перераспределения. Пользователь принимает сдвиг содержания при ручной перенумерации после удаления.

Старые ZIP не перезаписываются; сохраняются версии, manifest и снимки назначений. Прежние 335 назначений ТР1 импортированы из сентябрьской выдачи без нового выравнивания. Не удаляй их при проверке алгоритма; тесты выполняй на временных данных.

Перед передачей проверяй структуру банка, состав студентов и назначений, включение всех заданий, рисунки, пути, счётчики, состав и целостность ZIP. Баланс скобок и окружений не заменяет LaTeX-компиляцию. Не объявляй условия математически правильными по результатам тестов генератора.

При изменении кода запускай соответствующие тесты: docker compose run --build --rm -T utility python -m unittest discover -s tests -v. Не публикуй репозиторий и не отправляй сообщения коллегам без отдельного поручения.

Инструкции пользователя в беседе имеют приоритет. В отчёте различай реализованное, проверенное и ограничения; не вводи дополнительные согласования для уже порученной работы.
